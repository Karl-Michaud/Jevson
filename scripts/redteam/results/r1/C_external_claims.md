# Red team C: external claims in Jevson DESIGN.md, PLAN.md and README.md

## Competitive landscape the design misses

A fair summary: **Jevson's individual mechanisms all already exist somewhere. What is unclaimed is their combination as a general schema compiler.**

### 1. Inside the Jev ecosystem (the most important omission)

**TypeSafe's own cookbook** `pre_parsed_value_extraction` already publishes the §5.1/§5.3 mechanism, including the "cannot invent a value" guarantee and the `none` option: regex candidates, then a Jev `Choice` over the spans, then `NONE: "None of these is the requested value."`.

Other vendor cookbooks cover further pieces:

- `sde_cascade`: a per-field noul asks "is this value absent from the source?" as a verifier over LLM extraction, then escalates.
- `entity_alignment`: a three-way merge/curator/leave outcome, the same philosophy as §5.6.
- `citation_check`: string match, then supports / contradicts / says nothing.

**The vendor's playground** (`TypeSafeAI/typesafe-playground`) implements document extraction with offsets, candidate IDs and an explicit `null` choice.

**Community projects:**

- `gbesse/jev-extract` does typed records with candidate/absent fields, per-field provenance, request packing below limits, and chunk aggregation.
- `eortizs/jev-json-builder` (already in the table, mis-described) does candidate spans plus presence gates in TypeScript.
- `lzq-0529/jev-span` does candidate-window NER with reported F1.
- `choxos/jev-reviewer` (MIT, 2026-09-18, 36★) does systematic-review data extraction. Its method is `Choice "which line answers q?" (+ none)`, and "code copies the quote out of the file. Nothing is paraphrased, so nothing can be invented". It is **multi-file**, with the quote naming its file, which already covers Jevson's Phase 9 idea (verified: `gh api repos/choxos/jev-reviewer/readme`).
- Also listed in hellogumbo/awesome-jev: mateonunez/jod (semantic schemas over Jev, npm) and kieranklaassen/ruby_llm-typesafe (structured-output provider). Neither was checked in depth.

The design positions the candidate-plus-none idea as its "largest missed idea". In reality it is the vendor's documented usage pattern.

What is still genuinely unshipped in this ecosystem:

- a compiler from arbitrary JSON Schema / Pydantic to a **decision graph**, with nested objects, arrays and unions
- **decide-then-construct union branching**
- **level-batched keyed** execution with context budgeting
- **membership arrays with non-transitive-safe entity resolution** and overflow retention
- a **three-outcome central property** proven by a hostile adversarial suite
- **criteria-gated generative fields** (Phase 4). jevc and sde_cascade are adjacent but not the same.

### 2. Outside Jev

**Grounding (absent value):**

- Google **LangExtract** aligns each extraction to character intervals (exact or fuzzy) and sets `char_interval=None` when a value cannot be located. It has no confidence and no abstention.
- **Instructor** `CitationMixin`, the validation-context quote check, and the `Maybe` pattern verify quotes and offer uncalibrated abstention.
- **Guardrails** provenance validators (now archived) do the same for RAG text.
- **GLiNER** yields span-plus-score by construction.

Jevson's difference from these is thin on the absent-value row.

**Per-field confidence (silent confidence):**

- **Cleanlab TLM** `per_field_score` / `get_untrustworthy_fields()`
- **LlamaExtract** citations plus `confidence`
- **Reducto**, **Extend**, **Azure Document Intelligence** (documented as calibrated probability, including for "no value")
- **AWS Bedrock Data Automation**
- `structured-logprobs`
- the arXiv paper 2606.24420, a multi-signal confidence classifier with recalibration ("reduces ECE by 89%")
- **openextract** PR #232 (merged 2026-09-18)

Most of these are proprietary or black-box. None is deterministic, and most need extra LLM calls.

**Wrong entity:** Sensible's `multiple_possible_answers` and Extend's Review Agent "Ambiguity" flag it, but only as commercial post-hoc signals. **Unstract LLMChallenge** sets a field to `null` when two LLMs disagree. No open-source library performs an explicit calibrated choice among pre-verified candidates, apart from the Jev projects in section 1.

**Wrong branch:** no tool targeting union-branch selection was found. This is the one "nobody" cell that survives.

### Recommended repositioning

> Jevson generalises the "select, don't generate" pattern TypeSafe documents in its extraction cookbooks into a schema compiler: nested objects, unions decided before construction, source-grounded arrays with entity resolution, and a typed three-outcome result, verified by an adversarial suite. Grounding checks (LangExtract, Instructor) and per-field confidence (Cleanlab TLM, LlamaExtract, Azure DI) exist elsewhere. As far as we found, none combines pre-verified candidate spans, a calibrated none-of-these abstention and deterministic replay in an open library.

Phase 0 should add one column: "does typesafe-playground, jev-extract or the vendor cookbook already handle this?" Phase 8's fair comparison should cover these projects, not only `jev_jsonschema`.
