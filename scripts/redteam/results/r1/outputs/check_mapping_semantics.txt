(1) vendor api.md, answer types:
    Every answer carries a `type` matching its question. Choice and Score answers also carry a `confidence` between 0 to 1, derived from the answer's probability distribution. See [Confidence](/confidence).
    <ResponseField name="score" type="number" required>
    noul answer fields: ['type', 'noul'] -> no 'confidence' on noul; DESIGN §2 says noul returns 'boolean probability + confidence'
    score answer fields: ['type', 'score', 'legend', 'probabilities', 'confidence']

(2) integer field mapped to score:
    probs=[0.0, 0.05, 0.9, 0.05, 0.0] weighted_score=3.00 validates_as_integer=True round=3 argmax=3 (round has prob 0.90)
    probs=[0.45, 0.0, 0.0, 0.0, 0.55] weighted_score=3.20 validates_as_integer=False round=3 argmax=5 (round has prob 0.00)
    probs=[0.3, 0.3, 0.0, 0.0, 0.4] weighted_score=2.90 validates_as_integer=False round=3 argmax=5 (round has prob 0.00)

(3) 0–1 bounded numbers are usually VALUES, not probabilities:
    tax_rate                     source='VAT charged at 20%'         correct value=0.2; a noul p('tax_rate predicate') of e.g. 0.93 would be written as tax_rate=0.93 -> wrong-but-valid
    discount                     source='15% off list price'         correct value=0.15; a noul p('discount predicate') of e.g. 0.93 would be written as discount=0.93 -> wrong-but-valid
    ownership_share              source='holds 51% of the shares'    correct value=0.51; a noul p('ownership_share predicate') of e.g. 0.93 would be written as ownership_share=0.93 -> wrong-but-valid
    confidence (self-reported)   source='n/a'                        correct value=None; a noul p('confidence (self-reported) predicate') of e.g. 0.93 would be written as confidence (self-reported)=0.93 -> wrong-but-valid
    only a field whose *meaning* is 'probability that <predicate>' can take a noul p; the schema (minimum:0,maximum:1) cannot tell these apart

(4) integer ranges 2–10 that are counts (source-extractable), not ordinal ratings:
    bedrooms         range 1-10 -> 10 levels -> maps to score: True
    num_signatories  range 2-10 -> 9 levels -> maps to score: True
    quantity         range 1-10 -> 10 levels -> maps to score: True
    satisfaction     range 1-5 -> 5 levels -> maps to score: True

(5) bool at 0.5: p=0.5 exactly -> True with >=; False with >; the threshold direction is unspecified in the design
