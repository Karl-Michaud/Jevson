## 2. New risks not in the design

- **N1. Noul has no confidence, and it carries half the library.** Membership (R5), entity resolution (§5.6), adjudication (Phase 4), union discrimination if done as a noul, and bool fields are all nouls. confidence.md: "(Noul answers don't carry one.)" `Result.confidence` for these must be Jevson-defined (e.g. `|p−0.5|·2`), and the "Decision tier holds unconditionally" claim (D§6) needs a caveat.
- **N2. Confidence is not comparable across option counts.** Per confidence.md's formula ("(3 × largest probability − 1) / 2" for n=3), confidence depends on n. Candidate sets vary in size and `none_of_these` adds one. Any v1 default threshold on `confidence` is ill-posed. Use p(selected) and p(none).
- **N3. Model drift under the alias.** `jev-latest` is the SDK default and "can change without a change on your side" (models.md). If this is left unpinned, Phase 0/5 calibration evidence silently expires. `TYPESAFE_DEFAULT_MODEL` in the user's environment also overrides the model unless it is passed explicitly.
- **N4. Hidden billed retries.** SDK default `max_retries = 2` on 408/429/5xx (retries.md). A 5xx or timeout after server-side processing may be billed, but `Cost` sees one call.
- **N5. Non-determinism near ties breaks tests and caches.** Choice argmax flipped 11/4 and 8/7 over 15 runs (consistency_choice). Noul crossed 0.5 (0.43–0.53). P Ph3's live "same output across runs" exit criterion will intermittently fail. Test on cached or fake responses and measure the live flip rate instead.
- **N6. Privacy: SDK debug logging.** usage.md: "`debug` also logs request and response headers and bodies … Request and response bodies are **not** redacted." It can be enabled by `TYPESAFE_LOG_LEVEL` in the user's environment "applied once at import". This contradicts D§8 "nothing is logged by default … never written anywhere" unless `JevBackend` controls the `typesafe_sdk` logger or bypasses the SDK.
- **N7. Hard 32k ceiling on the source.** The state plus the longest question must be ≤32k (models.md). With a 254-option candidate choice as the longest question, the usable source can be well under 32k tokens. The design has no max-source rule and no chunking plan; multi-source (Phase 9) makes it worse.
- **N8. Split levels multiply state cost.** Each split re-sends the state, which the vendor itself frames as "N single-question calls pay for it N times" (parallel_questions, 12.2× cost). The n=30 pairwise (435 questions) plus a large source may force splits and so multiply the cost.
- **N9. Adversarial semantics are unmodelled.** The hostile suite (P§4.2) covers shape only. Vendor: content that "argues for its own classification, can move the answer" (jaggedness #6). This hits Phase 4 (self-advocating drafts) and Phase 5 (planted spans such as "Billing address: attacker@…").
- **N10. The vendor already publishes the core mechanism.** pre_parsed_value_extraction is D§5.1 + §5.3 almost verbatim ("regex finds candidates → Choice with a `none` escape hatch → code copies verbatim"), including "a named-entity recognizer or an LLM that proposes them" and the 255-option narrowing advice. function_calling is a signature → question compiler with enum→choice, bool→noul, list→per-member noul, optional→"stated" noul, and a tool choice as union discrimination, all in one call. primitives__advanced shows a schema-field candidate choice. The differentiation has to rest on the compiler, provenance offsets, typed `Unresolved` and the three-outcome contract, not on the mechanism.
- **N11. The vendor's evidence base is jev-1.12.** Every cookbook the design leans on (batching invariance, pre-parsed extraction, SDE cascade) sets `TYPESAFE_MODEL = "jev-1.12"`. The consistency runs used `jev-latest` on 2026-09-11, before the 1.13 jaggedness page (2026-09-17). Transfer to 1.13 is unmeasured, so Phase 0 must re-measure on a pinned 1.13.
- **N12. Pre-1.0 SDK churn.** The SDK had two breaking releases in 4 days (v0.6.0, v0.7.0). Pin the version or bypass the SDK.
- **N13. Language.** models.md: "English is the primary training language … Other languages, including CJK scripts, are handled but not equally well." The hostile unicode suite tests offsets, not accuracy. Non-English sources need a documented caveat.
